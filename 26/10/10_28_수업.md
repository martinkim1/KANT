## 1. NLP·LM·LLM의 관계

### 1.1 기본 개념

| 개념 | 의미 | 대표 작업 |
| --- | --- | --- |
| **NLP** | 인간의 언어를 컴퓨터가 처리하도록 하는 자연어 처리 분야 | 문장 분류, 감정 분석, 번역, 요약, 질의응답 |
| **LM** | 언어의 확률적 패턴을 학습하는 언어 모델 | 문맥에 맞는 단어·토큰 예측 |
| **LLM** | 대규모 데이터와 많은 매개변수를 사용해 학습한 언어 모델 | 문서 생성, 요약, 질의응답, 코드 작성 |

언어 모델의 발전 흐름:

**통계적 언어 모델 → 신경망 언어 모델 → 사전학습 언어 모델 → 대규모 언어 모델**

> **보완:** 모든 언어 모델이 다음 토큰 예측만 사용하는 것은 아니다. GPT는 다음 토큰 예측을, BERT는 가려진 토큰 예측을 대표적인 학습 방식으로 사용한다.

### 1.2 LLM이 기존 도구와 다른 점

- 자연어로 작업을 지시할 수 있다.
- 입력의 문맥을 바탕으로 사용자의 요구를 처리한다.
- 정보를 요약·변환·조합해 새로운 결과를 생성한다.
- 주어진 정보에서 새로운 결론을 도출하는 추론 작업을 수행할 수 있다.
- 멀티모달 모델은 텍스트와 함께 이미지 등도 처리한다.

**검색과의 차이**

| 구분 | 주요 역할 |
| --- | --- |
| 검색 | 관련 자료와 출처를 찾는다. |
| LLM | 입력과 학습된 패턴을 바탕으로 답변을 생성한다. |

> **보완:** 검색 기능을 연결한 LLM은 자료 검색과 답변 생성을 함께 수행할 수 있다. 이미지·영상 처리나 외부 도구 실행은 모델과 시스템이 지원해야 가능하다.

### 1.3 모델 성능 비교

강의는 여러 모델의 벤치마크 결과를 비교한다.

- 모델마다 언어 이해·수학·코딩 등 작업별 성능이 다르다.
- 하나의 점수만으로 모든 능력을 판단하기 어렵다.
- **MMLU**는 다양한 분야의 지식과 언어 이해 능력을 평가하는 벤치마크다.

> 강의에 제시된 모델 순위와 성능 수치는 해당 자료의 비교 시점에 해당한다.

## 2. 스케일링 법칙과 창발적 능력

### 2.1 스케일링 법칙

**모델 크기·학습 데이터·연산량의 규모에 따라 모델 성능이 어떻게 변하는지 설명하는 경험적 규칙**이다.

성능에 영향을 주는 주요 요소:

1. 모델 아키텍처
2. 모델 크기와 매개변수 수
3. 학습에 사용하는 연산 자원
4. 학습 데이터의 규모

**핵심:** 모델 성능은 매개변수 수 하나만으로 결정되지 않는다.

### 2.2 창발적 능력

강의는 모델이나 학습 규모가 커지면서 이전에는 잘 수행하지 못했던 능력이 나타나는 현상을 **창발적 능력(Emergent Ability)**으로 소개한다.

- 특정 규모 이후 일부 작업의 성능이 크게 높아지는 모습으로 설명한다.
- 언어 모델의 활용 범위가 확장되는 배경으로 제시한다.

> **보완:** 모든 능력이 특정 임계점에서 갑자기 생긴다고 일반화하기는 어렵다. 평가 방식에 따라서도 성능 변화가 급격하게 보일 수 있다.

## 3. 생성형 AI의 개념과 원리

### 3.1 생성형 AI란?

대규모 데이터에서 학습한 패턴을 바탕으로, 사용자의 프롬프트에 따라 새로운 콘텐츠를 만드는 기술이다.

| 생성 대상 | 활용 예시 |
| --- | --- |
| 텍스트 | 보고서, 요약문, 광고 문구 |
| 이미지 | 일러스트, 디자인 시안 |
| 음성·음악 | 음성 합성, 음악 제작 |
| 영상 | 영상 콘텐츠 제작 |
| 코드 | 프로그램 작성과 수정 |
| 프레젠테이션 | 발표 자료 초안 생성 |

### 3.2 텍스트 생성 원리

입력된 문맥을 바탕으로 **다음에 올 토큰의 확률을 예측하고, 이를 반복해 문장을 생성**한다.

예시:

> “나는 오늘 학교에 가서 …”
>
> 문맥에 따라 “공부했다”, “밥을 먹었다” 등의 후보가 서로 다른 확률을 가진다.

**핵심:** 자연스러운 문장을 생성하는 능력과 사실의 정확성은 별개다.

### 3.3 이미지 생성과 멀티모달

강의는 텍스트와 이미지의 의미를 벡터 표현으로 연결하는 **정렬(Alignment)** 개념을 소개한다.

- 텍스트와 이미지의 의미적 관계를 학습한다.
- 이를 바탕으로 텍스트에 맞는 이미지를 찾거나 생성하는 데 활용한다.

> **보완:** 이미지 생성 모델이 모두 텍스트 모델과 같은 방식으로 작동하는 것은 아니다. 확산 모델 등 서로 다른 생성 구조를 사용할 수 있다.

### 3.4 강의에서 제시한 발전 흐름

| 시기 | 주요 변화 |
| --- | --- |
| 2017년 | Transformer 구조 등장 |
| 2022년 | ChatGPT를 통한 대화형 생성 AI 대중화 |
| 2023년 | GPT-4와 멀티모달 활용 확대 |
| 2024~2025년 | 계획과 도구 실행을 결합한 AI Agent 활용 확대 |

## 4. 주요 AI 용어와 기술 흐름

### 4.1 용어 비교

| 용어 | 핵심 의미 |
| --- | --- |
| **인공지능(AI)** | 학습·추론·판단·문제 해결 등 지능적 작업을 수행하는 기술 분야 |
| **머신러닝(ML)** | 사람이 모든 규칙을 작성하는 대신 데이터에서 패턴을 학습하는 방법 |
| **딥러닝(DL)** | 여러 층의 인공신경망을 이용하는 머신러닝 방법 |
| **생성형 AI** | 학습한 패턴을 바탕으로 새로운 콘텐츠를 생성하는 AI |
| **LLM** | 대규모로 학습한 언어 모델 |
| **파운데이션 모델** | 대규모 사전학습을 바탕으로 여러 작업에 적용할 수 있는 범용 모델 |

**포함 관계:** AI 안에 머신러닝이 있고, 머신러닝 안에 딥러닝이 있다.

생성형 AI는 **생성 기능**, LLM은 **언어 모델**, 파운데이션 모델은 **다양한 작업에 활용되는 사전학습 기반**에 초점을 둔 개념이다.

### 4.2 강의에서 소개한 주요 흐름

| 분야 | 핵심 방향 |
| --- | --- |
| 생성형 AI | 텍스트·이미지·음성·영상 등의 콘텐츠 생성 |
| 멀티모달 | 여러 종류의 데이터를 함께 처리 |
| AI Agent | 목표에 따라 계획하고 도구를 사용해 작업 수행 |
| 온디바이스 AI | 사용자 기기에서 AI 실행 |
| RAG·기업형 AI | 외부 자료나 기업 데이터를 연결해 답변 생성 |
| AI 거버넌스 | AI의 책임·안전·보안·운영 기준 관리 |

> 각 분야의 짧은 정의는 이해를 위한 보완 설명이다.

강의는 데이터·센싱 기술·컴퓨팅 인프라를 AI 발전의 기반으로 소개하고, 이미지 생성·국방·에이전트 등 활용 사례를 제시한다.

## 5. AI의 한계와 주요 이슈

### 5.1 환각: 그럴듯하지만 잘못된 답변

**환각(Hallucination)**은 사실이나 제공된 근거와 맞지 않는 내용을 사실처럼 생성하는 현상이다.

강의는 LLM을 **손실 정보 압축기**에 비유한다.

1. 학습 데이터의 패턴과 관계가 매개변수에 반영된다.
2. 학습 데이터를 원문 그대로 정확하게 보관하는 데이터베이스는 아니다.
3. 답변을 생성하는 과정에서 세부 사실이 틀리거나 없는 근거를 만들 수 있다.

> **보완:** 손실 압축은 이해를 돕는 비유다. 환각의 원인을 이것 하나로 모두 설명할 수는 없다. 학습 데이터에 없는 내용을 생성했다고 해서 모두 환각인 것도 아니다.

### 5.2 유해 응답과 편향

- 민감한 요청에 부적절하거나 안전하지 않은 답변을 생성할 수 있다.
- 강의의 **Violation Percentage**는 이런 위반 응답의 비율을 뜻한다.
- 학습 데이터에 포함된 사회적 편견이 결과에 반영될 수 있다.

**핵심:** 답변이 자연스럽다는 이유만으로 공정하고 안전하다고 판단하지 않는다.

### 5.3 윤리

| 원칙 | 핵심 내용 |
| --- | --- |
| 프라이버시 보호 | 개인정보를 보호하고 불필요한 수집을 피한다. |
| 책임 있는 사용 | 불법적이거나 해로운 활동에 악용하지 않는다. |
| 정확성 | 근거를 확인하고 오류가 있으면 수정한다. |
| 한계 인식 | AI 답변을 무조건 신뢰하지 않는다. |

### 5.4 저작권

강의는 AI 생성 이미지와 공모전 사례를 통해 저작권·창작의 쟁점을 소개한다.

검토할 문제:

- 학습 자료와 생성 결과물의 권리
- 타인의 작품과 유사한 결과물
- 창작 과정에서 사람과 AI의 기여

> 위 항목은 사례의 쟁점을 정리한 것이며, 개별 결과물의 법적 판단을 확정한 내용은 아니다.

### 5.5 비용과 자원

AI 활용에는 다음 비용이 발생한다.

- 모델 학습·추론을 위한 연산 비용
- 서버와 데이터센터의 전력 소비
- API 사용량에 따른 비용

**토큰(Token)**은 모델이 텍스트를 처리하는 단위다.

- `1M tokens`는 100만 토큰이다.
- 토큰 수와 글자 수·단어 수의 관계는 언어와 토크나이저에 따라 다르다.
- 강의는 일정 성능을 충족하는 모델의 토큰당 비용이 낮아지는 추세를 소개한다.

> 제시된 가격과 전력 소비 수치는 자료의 비교·추정 시점 기준이다.

### 5.6 보안

외부 AI 서비스에 입력한 정보가 노출될 위험을 고려해야 한다.

- 회사 기밀
- 고객 개인정보
- 내부 문서와 소스코드

**핵심:** 입력할 정보의 민감성과 서비스 이용 조건을 확인한다.

### 5.7 최신 정보의 한계

- 모델 자체의 학습 지식에는 기준 시점이 있다.
- 학습 이후 발생한 사건은 모르거나 부정확하게 답할 수 있다.
- 빠르게 바뀌는 정보는 최신 근거 확인이 필요하다.

> **보완:** 검색이나 외부 자료를 연결하면 최신 정보를 참고할 수 있지만, 출처와 답변의 정확성 확인은 여전히 필요하다.

## 6. 프롬프트 엔지니어링

### 6.1 기본 개념

- **프롬프트:** AI에 작업을 요청하기 위해 제공하는 지시와 입력.
- **프롬프트 엔지니어링:** 원하는 결과를 얻도록 지시와 입력을 설계하고 개선하는 과정.

### 6.2 학습과 프롬프트의 차이

| 개념 | 의미 |
| --- | --- |
| **Instruction Tuning** | 지시와 응답 사례로 모델을 추가 학습시키는 과정 |
| **In-Context Learning** | 입력 문맥과 예시를 바탕으로 작업 패턴을 적용하는 현상 |
| **Prompt Engineering** | 사용자가 지시·맥락·예시·출력 조건을 설계하는 기술 |

> **보완:** 일반적인 프롬프트 입력이나 In-Context Learning은 모델의 가중치를 업데이트하지 않는다. Instruction Tuning과 매번 순서대로 실행되는 별도 학습 단계도 아니다.

### 6.3 프롬프트의 기본 구성

| 구성 요소 | 내용 |
| --- | --- |
| 명령 | 무엇을 수행할 것인가? |
| 맥락 | 어떤 상황과 배경을 고려할 것인가? |
| 입력 데이터 | 무엇을 분석하거나 처리할 것인가? |
| 출력 조건 | 어떤 형태로 답할 것인가? |

### 6.4 실무에서 활용하는 다섯 요소

| 요소 | 의미 | 예시 |
| --- | --- | --- |
| **역할(Role)** | 수행할 관점과 역할 | 식품 마케팅 전문가 |
| **맥락(Context)** | 배경·목적·대상 | MZ세대 대상 건강 간편식 출시 |
| **명령(Instruction)** | 구체적인 작업 | 홍보 콘텐츠 시리즈 기획 |
| **형식(Format)** | 결과물의 구조 | 설명과 요약 표 |
| **어조(Tone)** | 말투와 분위기 | 밝고 신뢰감 있는 표현 |

간단히는 **RIO**로 정리할 수 있다.

- **R — Role:** 역할
- **I — Instruction:** 구체적인 지시
- **O — Output:** 기대하는 출력 형태

### 6.5 좋은 프롬프트를 만드는 방법

1. 대상·목적·기간 등 필요한 세부정보를 제공한다.
2. 작업에 적절한 역할을 지정한다.
3. 제목과 구분 기호로 지시와 자료를 나눈다.
4. 필요한 작업 순서를 명시한다.
5. 원하는 결과의 예시를 제공한다.
6. 출력 길이와 형식을 정한다.

**모호한 요청**

> 최근 소비 패턴을 알려줘.

**구체적인 요청**

> 대한민국의 최근 1년간 소비 패턴을 조사해줘. 조사 기간과 통계 출처를 명시하고, 주요 변화·근거 수치·해석의 한계를 표로 정리해줘.

### 6.6 재사용할 수 있는 프롬프트 틀

# 역할

# 맥락

참고해야 할 배경은 [배경]입니다.

# 입력 자료

## 7. 프롬프트 기술과 사업 경쟁력

강의는 프롬프트 공유 플랫폼과 마켓플레이스, 관련 직업에 대한 다양한 전망을 소개한다.

핵심 쟁점:

- 같은 프롬프트에서도 서로 다른 결과가 나올 수 있다.
- 모델이 발전하면 복잡한 프롬프트의 필요성이 줄어들 수 있다.
- 프롬프트 작성 기술만으로 지속적인 경쟁력을 확보할 수 있는지 검토해야 한다.

### 서드파티와 근원적 경쟁력

**서드파티(Third Party)**는 다른 기업의 핵심 기술이나 플랫폼을 활용해 파생 상품·서비스를 만드는 기업을 뜻한다.

강의는 스마트폰 액세서리 시장을 예로 들어 다음 질문을 제시한다.

> 다른 기업의 AI 기술을 활용하는 서비스는 무엇으로 고유한 경쟁력을 만들 것인가?

**학습 포인트:** 프롬프트 작성과 함께 문제 정의·도메인 이해·데이터 활용·결과 평가 능력을 연결해 생각한다.

> 채용 시장 변화와 직업 전망에 관한 슬라이드는 강의에서 소개한 자료와 견해이며, 현재 시장 전체에 대한 확정적인 결론은 아니다.

## 8. AI 활용 도구

### 8.1 NotebookLM

강의는 NotebookLM을 **사용자가 제공한 소스 자료를 바탕으로 답변하는 AI 노트·연구 도구**로 소개한다.

활용 방향:

- 자료 요약과 질의응답
- 여러 문서의 내용 비교
- 개인·업무 자료를 활용한 지식 정리
- 답변의 근거 확인

**핵심:** 일반적인 질문뿐 아니라, 제공한 자료를 바탕으로 답변을 검토하는 데 활용한다.

> **보완:** 소스 기반 도구라도 해석 오류나 근거 누락이 생길 수 있다. 자료 기반 질의응답 도구와 외부 작업을 자율적으로 수행하는 범용 Agent는 구분해야 한다.

### 8.2 n8n

강의는 AI 활용 도구로 n8n을 소개한다.

> **보완:** n8n은 여러 서비스와 API를 연결해 작업 흐름을 자동화하는 도구다. 해당 슬라이드에서는 상세한 사용 절차를 설명하지 않는다.

## 9. 실습: 카페 할인 행사의 성과 분석

### 9.1 제공된 자료

카페 A는 9월 한 달 동안 할인 행사를 진행했다. 두 달의 영업일 수는 같다.

| 지표 | 8월 | 9월 |
| --- | --- | --- |
| 매출 | 1,000만 원 | 1,200만 원 |
| 주문 수 | 1,000건 | 1,500건 |
| 영업이익 | 200만 원 | 120만 원 |

추가 조건:

- 9월에는 홍보와 주문 증가 대응을 위한 비용이 늘었다.
- 신규 고객의 재구매 여부는 조사하지 않았다.
- 행사하지 않은 비교 매장 자료가 없다.
- 지난해 같은 기간 자료가 없다.

### 9.2 수치 계산

아래는 제공된 자료를 바탕으로 계산한 결과다.

| 지표 | 8월 | 9월 | 변화 |
| --- | --- | --- | --- |
| 매출 | 1,000만 원 | 1,200만 원 | **20% 증가** |
| 주문 수 | 1,000건 | 1,500건 | **50% 증가** |
| 주문당 평균 매출 | 10,000원 | 8,000원 | **20% 감소** |
| 영업이익 | 200만 원 | 120만 원 | **40% 감소** |
| 영업이익률 | 20% | 10% | **10%p 하락** |

계산식:

- 매출 증가율 = `(1,200 - 1,000) / 1,000 × 100 = 20%`
- 주문 수 증가율 = `(1,500 - 1,000) / 1,000 × 100 = 50%`
- 8월 주문당 평균 매출 = `1,000만 원 / 1,000건 = 10,000원`
- 9월 주문당 평균 매출 = `1,200만 원 / 1,500건 = 8,000원`
- 영업이익 변화율 = `(120 - 200) / 200 × 100 = -40%`
- 영업이익률 = `영업이익 / 매출 × 100`

### 9.3 실습 진행 순서

| 단계 | 요청 내용 | 학습 목적 |
| --- | --- | --- |
| **CASE 1** | 매출·주문 자료만으로 요약하고 증가율 계산 | 주어진 자료로 가능한 판단 확인 |
| **CASE 2** | 영업이익·운영 자료를 추가해 다시 분석 | 추가 정보에 따라 판단이 달라지는지 확인 |
| **CASE 3** | 인과관계와 장기 성과를 확정할 수 있는지 검토 | 근거와 판단의 한계 구분 |

### 9.4 확인된 사실과 판단의 한계

| 구분 | 내용 |
| --- | --- |
| 확인된 사실 | 행사 기간에 매출과 주문 수가 증가했다. |
| 확인된 사실 | 주문당 평균 매출과 영업이익이 감소했다. |
| 확정하기 어려운 주장 | 할인 행사 때문에 매출이 증가했다. |
| 확정하기 어려운 주장 | 이번 행사는 장기적으로 성공했다. |

**성과 해석**

- 매출·주문 확대라는 측면에서는 증가가 확인된다.
- 단기 수익성은 악화됐다.
- 비교 자료가 없어 매출 증가의 원인을 할인 행사로 확정하기 어렵다.
- 재구매 자료가 없어 장기 성과를 판단하기 어렵다.

### 9.5 추가로 필요한 데이터

- 신규 고객의 재구매율과 유지율
- 행사 종료 후 매출과 영업이익
- 할인·광고·추가 인건비 등 비용 내역
- 비교 매장의 같은 기간 성과
- 지난해 같은 기간의 매출과 계절적 변화

### 9.6 최종 보고서 구성

1. **자료에서 확인한 사실**
2. **현재 자료만으로 판단하기 어려운 것**
3. **다음 의사결정을 위해 추가로 확인할 사항**

**핵심:** AI는 자료 정리와 분석을 도울 수 있지만, 근거의 충분성을 검토하고 최종 의사결정을 내리는 책임은 사용자에게 있다.

## 10. 복습용 핵심 정리

| 주제 | 기억할 내용 |
| --- | --- |
| LLM | 문맥과 학습된 패턴을 바탕으로 결과를 생성한다. |
| 스케일링 | 모델·데이터·연산 규모가 성능에 영향을 준다. |
| 생성형 AI | 텍스트·이미지·음성·영상 등 새로운 콘텐츠를 만든다. |
| 환각 | 자연스러운 답변도 사실이나 근거와 다를 수 있다. |
| 편향 | 학습 데이터의 편견이 출력에 반영될 수 있다. |
| 보안 | 개인정보와 내부 기밀의 입력에 주의한다. |
| 최신성 | 모델의 학습 지식과 최신 외부 자료를 구분한다. |
| 프롬프트 | 역할·맥락·명령·형식·어조를 명확히 한다. |
| 소스 기반 활용 | 답변과 원문 근거를 함께 확인한다. |
| 성과 평가 | 단일 지표뿐 아니라 비용·수익·장기 효과도 확인한다. |
| 인과관계 | 행사 기간의 변화만으로 행사 효과를 확정하지 않는다. |
| 업무 책임 | AI의 분석 결과를 검토하고 최종 판단한다. |
